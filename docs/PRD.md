# FitWell Journal — 产品需求文档（PRD）v0.1

> 健身健康日志：记录吃饭时间与睡眠时间，提供食谱推荐与做法，基于规则引擎输出代谢规律分、睡眠规律分与趋势洞察。
> **定位声明：本产品输出"趋势洞察"，不是医疗器械，不提供任何诊断。**

## 1. 产品定位

- **一句话**：给健身人群的轻量代谢健康日志——30 秒记录，看懂自己的进食与睡眠规律。
- **目标用户**：有健身习惯、关注体成分与饮食质量、愿意记录但讨厌复杂表单的人。
- **核心假设**：
  1. 进食时间结构（进食窗口、末餐时点、进食频率）与睡眠规律性，是用户自己肉眼看不出、但对代谢健康有意义的信号；
  2. 轻度录入 + 可解释的趋势反馈，能形成 7 天以上的留存；
  3. 食谱推荐是高频刚需入口，能带动记录行为。

## 2. 设计原则（产品级约束）

| 原则 | 含义 |
|---|---|
| **只记客观事实** | 时间、次数、克数、体重——事实没有对错。主观打分（心情/压力/精力/饥饿/渴望）已于 v0.1.1 全部移除：它们主观、不可控、且制造填写焦虑 |
| **健身人的小闹钟** | 产品的本质是节奏提示（进食窗口、收尾、就寝），记录是为提示服务的 |
| **减少焦虑** | 不追打卡、不警告、缺记录只说"想起来再补"；分数弱化为文字档位（很稳/不错/可调整） |
| 轻度使用 | 核心层每天 30 秒填完；展开层全部可选；不填不影响功能可用 |
| 趋势为王 | 输出趋势、档位、相关性提示，不做单点结论、不做诊断 |
| 可解释 | 每个档位和卡片都能展开看到"为什么" |
| 措辞红线 | 只说"数据显示…趋势""建议关注"；禁止出现"你有 XX 病/XX 抵抗"等诊断语言 |

## 3. 功能范围

### 3.1 MVP v0.1（本期交付）

| 模块 | 功能 | 状态 |
|---|---|---|
| 记录 | 一餐（时间/类型/内容可选）、睡眠（起止/质量）、体重、训练、体检血值 | ✅ |
| **今日节奏（小闹钟）** | 按进食窗口/就寝目标实时提示当前阶段与下一动作（晨间/进食窗口/收尾/睡前/睡眠时段），温和不评判 | ✅ v0.1.1 |
| 规则引擎 | 代谢规律分（进食窗口/末餐-入睡间隔/进食节奏/睡前进食）、睡眠规律分（时长/就寝规律/起床规律/社交时差），呈现为文字档位 | ✅ |
| 洞察 | 趋势卡片（周环比）、关联卡片（睡眠↔加餐、睡前进食↔睡眠、进食窗口↔睡眠、训练↔入睡），全部基于客观数据 | ✅ |
| 周报 | 档位卡 + factor 明细 + 卡片流 + SVG 折线图（进食窗口/睡眠时长） | ✅ |
| 食谱 | 内置 12 道健身食谱，按目标/餐次筛选，含做法与食用时机 | ✅ |
| 数据 | JSON 文件存储、导出/导入 | ✅ |

### 3.2 v0.2（体验升级）

- 拍照识食（多模态 LLM）、LLM 对话式营养教练（LLM 只负责表达，判断逻辑仍在规则引擎）
- 录入补全：补剂、咖啡因/酒精**时点**、饮水、午睡、夜间醒来
- 更多关联卡片、月报、数据图鉴

### 3.3 v0.3（数据护城河）

- 可穿戴接入（Apple Health / 华为运动健康 / Garmin）自动同步睡眠、静息心率、HRV
- 体检血值录入完善（空腹血糖/胰岛素/HbA1c/血脂）→ 代谢指标趋势对比
- 有条件则接入 CGM（连续血糖监测），这是"代谢洞察"真正有分量的数据源

### 3.4 商业化路径（练手之后）

1. **订阅制**：免费记录 + 付费深度周报/个性化食谱计划（健康 App 最成熟模式）
2. **增值解读**：体检报告趋势解读（敏感区，措辞与合规需单独评审）
3. **B2B**：企业健康 / 健身房联名

## 4. 数据分层（"入口全"与"轻度"的调和）

| 层 | 字段 | 录入频率 | 录入成本 |
|---|---|---|---|
| 核心层 | 第一餐/最后一餐时间、睡眠起止 | 每天 | ≤30 秒 |
| 展开层 | 吃了什么、训练、体重、腰围体脂 | 可选 | 按需 |
| 低频层 | 体检血值（空腹血糖、胰岛素、HbA1c、血脂） | 月/季度 | 一次数分钟 |
| 自动化（v0.3） | 睡眠、静息心率、HRV | 自动 | 0 |
| 设置（一次性） | 进食窗口目标、就寝/起床目标 | 一次 | 驱动"今日节奏" |

> v0.1.1 起主观打分（心情/压力/精力/饥饿/渴望）整体移除：它们不是"可控的数据"，且加重填写负担。

完整字段见 [data-model.md](data-model.md)；洞察规则定义见 [insights-rules.md](insights-rules.md)。

## 5. 成功指标（练手期）

- 单人连续记录 ≥ 14 天（验证录入摩擦可控）
- 周报页面每次更新被打开 ≥ 1 次（验证洞察有吸引力）
- 代码结构可作为作品集展示：核心逻辑零第三方依赖、单元测试覆盖规则引擎

## 6. 风险与合规

- **医疗边界**：措辞红线写入产品规范与代码注释；周报固定展示免责声明；不收集诊断结论。
- **隐私**：健康数据属敏感个人信息。MVP 本地存储（JSON 文件），不上传第三方；商业化前必须补：隐私政策、数据加密、合规评审（个保法/GDPR）。
- **科学有效性**：评分与关联均为启发式规则，样本量小的关联卡片自动隐藏（证据天数不足不展示）。
